# Базовый набор, изменения и граница ответственности

## Базовый набор

Базовый набор (baseline) — явно обозначенный существующий набор требований,
процессов или as-is-описание, либо источник, однозначно разделяющий
as-is и to-be. Разделы того же брифа базовым набором не считаются: текущие
факты внутри анализируемого источника — `CTX`.

Если базовый набор не передан, напиши одну строку: `Сравнение невозможно:
существующий набор требований не предоставлен`. Не создавай фиктивных
`DELTA`. Упомянутый, но не приложенный документ — `CTX` и `GAP`, а не
изученный базовый набор.

## Изменения

Строй записи изменений (`DELTA-001`) только при наличии обоих полюсов:
элемента базового набора и нового элемента. Сравнивай тип, субъект,
действие, объект, условия, результат и область действия, а не только
текст. Разница уровня детализации — не конфликт; нормализация
формулировки — не изменение.

Виды изменений:

- `новое` — аналога в baseline нет;
- `уточнено` — детализация без изменения обязательства;
- `изменено` — изменено обязательство или область действия;
- `заменено / исключено` — элемент заменяется или отменяется;
- `дубликат` — семантическое совпадение с baseline;
- `конфликт` — нельзя выполнить одновременно.

Выводи только изменения и конфликты; неизменённые строки опускай.

| ID в базовом наборе | Новый ID | Вид изменения | Комментарий |
|---|---|---|---|
| FR-014 | FR-001 | новое | ... |

## Граница ответственности

Различай роли сущностей; совмещение ролей — только при отдельном
подтверждении:

| Роль | Что означает | Что не следует автоматически |
|---|---|---|
| Канал / интерфейс | Точка доступа пользователя | Исполнение операции, хранение данных |
| АС / компонент | Техническая граница реализации | Владение бизнес-результатом |
| Исполнитель операции | Выполняет целевое действие | Быть каналом или источником истины |
| Оркестратор | Координирует шаги и участников | Самостоятельное выполнение каждого шага |
| Источник истины | Авторитетно хранит объект или атрибут | Владение местом выполнения операции |
| Владелец / контролёр | Принимает решение, правило или результат | Техническое исполнение функции |

Упоминание приложения, портала или API подтверждает канал, но не назначает
его исполнителем, хранилищем или источником истины. До подтверждения
распределения ответственности используй нейтральную формулировку: «решение
в анализируемой границе принимает запрос и предоставляет наблюдаемый
результат».

Названия АС, каналов, ролей, бизнес-объектов и статусов бери только из
анализируемых источников или переданных справочников и моделей; не подбирай
правдоподобное имя и не исправляй термин «по смыслу». Если объект нужен для
формулировки, но нигде не назван, — пиши «неизвестная АС / объект» со
ссылкой на `GAP` о предоставлении справочника или модели данных.

## Конфликты

Проверяй конфликты по ролям, объектам, состояниям, срокам, правилам,
источникам истины и ограничениям. Различай конфликт (нельзя выполнить
одновременно), неизвестность и неполную детализацию: последние две — не
статус `Конфликтует`.
