Правила глобальной консолидации:

1. Считай все переданные единицы единым источником. Не ограничивай результат
последней единицей и не выдавай независимые отчёты.
2. Сохрани только подтверждённые BR, SR, FR, NFR, TR и CON. Контекст, GAP,
HYP и TERM храни отдельно; неподтверждённый scope не превращай в требование.
3. Закон, договор, стандарт, политика или прямо названное обязательное правило
с подтверждённым obligation остаётся CON, а не заменяется NFR. NFR добавляй
отдельно только при наличии проверяемого качества решения.
4. Сохраняй атомарность: отдельные действия и альтернативные наблюдаемые
результаты — отдельные SR/FR. Не склеивай, например, показ суммы и показ
причины отказа в одну FR. Для явно названной роли оставляй SR с ролью, для
подтверждённого поведения — FR; разрыв BR → SR → FR/NFR фиксируй GAP.
5. Удали семантические дубликаты, сохрани наиболее полную доказательную цитату
и перенеси связи на оставшуюся запись. Не удаляй независимое обязательство
только из-за похожей формулировки.
6. Назначь глобально уникальные ID с отдельной нумерацией по типу: BR-001,
SR-001, FR-001, NFR-001, TR-001, CON-001, CTX-001, GAP-001, HYP-001,
TERM-001, DELTA-001. Не оставляй коллизии ID от отдельных единиц.
7. Все source должны сохранять artifactId и locator исходных единиц. Если
доказательства нет, создай GAP, а не правдоподобную цитату.
8. Перестрой traceability на глобальные ID и оставь только существующие записи.
У каждого link непустые from, to, relation и допустимый status. Явные связи
помечай «Подтверждено источником», аналитические — «Предполагается».
9. Сравнивай с baseline только со статусом AVAILABLE. Без baseline delta пустой
и явно сообщи, что сравнение невозможно. Для UNAVAILABLE создай GAP, не DELTA.
10. Не назначай роли, системы, объекты, правила, числа или ответственность,
которых нет в материалах. CON создавай только с непустым подтверждённым
obligation; при отсутствии доказательства фиксируй GAP.
11. Объедини вопросы, оставь 3–7 приоритетных вопросов, каждый с gapId,
addressee, priority P0/P1/P2 и формулировкой одного решения.
12. outcome — PARTIAL при необработанных единицах или пробелах охвата;
COMPLETE — только при полном охвате доступных единиц.

  "scope": {"partial": false, "units": []}

Все массивы обязательны. У requirements должны быть source, provenance,
quality и связи своего типа; source имеет artifactId, locator, quote. Все
ссылки должны разрешаться в объединённом результате. Счётчики summary.counts
должны точно совпадать с длинами массивов. Не включай текст вне JSON.
