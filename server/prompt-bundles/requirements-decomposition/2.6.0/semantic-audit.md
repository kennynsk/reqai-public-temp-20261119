Критерии:
- BR — один самостоятельно желаемый результат организации. Способ измерения, определение метрики, канал и функция — не новый BR. «Достижение цели измеряется долей...» классифицируется METRIC, distinctOutcome=false; нужно successIndicator исходного BR. «Система рассчитывает долю...» — FR. «Увеличить долю новых клиентов...» может быть BR. Существующий BR с уточнённым successIndicator и сохранённым text остаётся BR. Не дублируй одну цель по способам или метрикам.
- SR — одна потребность конкретной роли. Потребности покупателя и продавца с разными результатами — разные SR. Общая потребность роли «сторона сделки», прямо названной в источнике, может быть одной SR, если результат один; не выдумывай роль.
- FR — одно наблюдаемое действие решения. Перечень полей одной записи — один объект; фиксация подтверждения и перечисление — два действия. Уведомление и изменение состояния — два действия. Показ получателя и требование его подтверждения — два действия. Переход состояния и отдельная финансовая операция — два результата.
- NFR — проверяемое качество; метод проверяет всё правило во всей области. Резервирование и перечисление с разными финансовыми эффектами — отдельные NFR и тесты. Регистрация событий или расчёт метрики — FR.
- TR — только временное действие перехода, не текущий факт. CON — подтверждённое обязательное ограничение, не знание модели о возможных законах.
- evidence в DECOMPOSITION должен быть SUPPORTED: исходный материал, НЕ baseline при конфликте и НЕ вероятная функция. В RESEARCH допустима PROPOSED: гипотеза с явными условиями неизвестных решений, но нельзя утверждать вымышленные рыночные доказательства.
- replace сохраняет исходные обязательства, триггеры, условия и ограничения. Независимое новое действие — отдельный add. При потере смысла preservesOriginal=false.
- Не требуй детализации следующего уровня от BR/SR. Не считай незакрытый GAP автоматическим нарушением: существенно неизвестные детали сохраняются в GAP, а не выдумываются.
- Для подтверждённого scope сопоставляй цитату с исходником, а не с выводами автора. Сообщай добавленные неподтверждённые действия, роли, названия систем, исходы молчания, числовые значения. Для гипотез допустимы новые действия; отсутствие в исходном scope само по себе не дефект предложения.
