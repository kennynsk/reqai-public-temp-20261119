# Проверка управляемого уточнения — 2026-09-12

Реализация находится в ветке `codex/requirements-list-detail`. Изменение расширяет существующий диалог: отдельный GAP prompt 2.0.0, валидируемый пакет ответа и правок, явное принятие, частичное уточнение, актуальные основания и фиксация решения при общем сохранении.

## Автоматические проверки

- 155 тестов клиента в восьми связанных наборах прошли: `DiscussionPanel`, `ReviewQuestions`, `AsyncJobWorkspace`, `AsyncJobWorkspace.components`, `RequirementListWorkspace`, `review-metadata`, `review-state`, `gap-clarification`.
- После финальных изменений подписей, мобильной кнопки и фокуса повторно прошли 19 тестов затронутых UI-компонентов.
- 28 тестов сервера прошли: `gap-clarification`, `requirement-discussion-service`, `review-metadata`, `requirements-version`. PostgreSQL concurrency-тест из `review-save-postgres` пропущен без тестового подключения; изменения схемы БД не требуются.
- Клиентские сценарии напрямую проверяют нормализацию сервером: атомарное принятие, частичное → полное до сохранения и через сохранённую версию, пакет без правок, последующая ручная правка, история принятия и инвалидирование связанных подтверждений.
- Устаревание проверено для формулировки, требования без правки, источника, вопроса, термина, связей и состояния GAP. Ответ дополнительно проверяется существующим механизмом `gapBases` при принятии в workspace.
- Проверены неизвестные/дублирующиеся targets, запрещённые поля, неполные подтверждения, исключённый контекст, совместимость старых ошибочных отметок TERM/CTX, отсутствие повторной отправки при двойном клике, повтор с тем же ключом после неопределённой сетевой ошибки и отсутствие возврата старого пакета после нового ответа без правок.
- `npm run lint`, `npm run build`, `openspec validate add-requirement-ai-discussion --strict`, `git diff --check` проходят.

## Проверка интерфейса

На синтетическом реестре переговорных через реальные компоненты пройден путь «Помочь уточнить» → «Начать уточнение» → ответ обычными словами → сравнение критерия успеха → «Применить уточнение и закрыть вопрос» → общий save. До принятия данные не изменяются. После принятия вопрос закрыт в черновике, после сохранения показан сохранённый статус. Источник и исходная формулировка GAP сохраняются.

Панель проверена на обычном экране и внутри рамки 390 × 844; ширина содержимого равна ширине доступной области, горизонтальной прокрутки нет. Кнопка отправки не переносится внутри слова, история имеет собственную прокрутку, новый ответ становится видимым, поле ответа получает фокус после отправки. После закрытия GAP не показывается прежняя подсказка следующего шага. Ручной путь без AI остаётся покрыт регрессией.

Ответы AI в демонстрации фиксированные. Новая генерация на пользовательской задаче и изменение её требований не запускались; качество диалога с живой моделью остаётся для пользовательской проверки.

## Локальный запуск

Frontend работает в dev-контейнере с подключённой рабочей папкой. API использовал отдельный ранее собранный образ: обновлён командой `docker compose -f compose.yaml build reqai-api` и `docker compose -f compose.yaml up -d --no-deps reqai-api`. Готовность API — healthy. SHA-256 четырёх изменённых серверных модулей внутри контейнера совпали с файлами рабочей ветки. База и остальные контейнеры не пересоздавались.

Ветка изолирует историю Git; локальный frontend показывает текущую рабочую папку, а API — последний собранный образ. Для отката локального поведения требуется переключить код и пересобрать API.

## Границы первой версии

Помощник изменяет существующие связанные требования. Создание новых требований, редактирование TERM/CTX, качества и связей остаются ручными действиями; prompt требует перечислить их как незавершённые шаги. Статус качества требования не становится «Готово» автоматически после закрытия одного GAP. Обычные текстовые предложения и невалидные ответы никогда не закрывают вопрос.
