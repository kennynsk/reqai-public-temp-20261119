## Design

Веб-настройки хранят выбор рядом с моделью, температурой и reasoning в существующем хранилище предпочтений пользователя. Оба маршрута создания принимают необязательный булев `criticEnabled`. Сервис фиксирует его в снимке задачи, где отсутствие поля означает включённый режим. Повтор из API использует исходный снимок. Повтор исследования из веб-интерфейса считается новым запуском и использует сохранённое тело запроса при повторной отправке.

В режиме без критика воркер пропускает отдельные LLM-вызовы проверки и семантического исправления. Генерация по BABOK, нормализация, правила структуры и исправление формата остаются в обычном пути. Для структурированного результата записывается `semanticValidation.status = SKIPPED`. Журнал показывает причину пропуска. При сбое включённого критика работает существующий частичный результат с черновиком декомпозиции или сохранёнными входными требованиями исследования.

Первичный запуск и серверный retry декомпозиции используют `JOB_DECOMPOSITION_DEADLINE_MS`. Исследование сохраняет текущий выбор меньшего значения из серверного дедлайна и бюджета профиля. Для компактной сборки декомпозиции применять 15 минут исполнения активности и 16 минут с учётом очереди через маркер совместимости Temporal.
