## Why

After incomplete AI verification, the recovery screen starts with an empty registry and requires one action per formulation. The user needs to review the available requirements together and see concrete questions in context.

## What Changes

- Show recovered typed formulations immediately in the existing editable registry, with one notice that explains what to review.
- Surface available linked questions beside the relevant requirement and retain the original response for reference.
- Preserve typed traceability so the recovered requirements retain their hierarchy.
- Save and finalize through the existing requirements-version workflow.

## Capabilities

### Modified Capabilities

- `frontend-guided-workflow` displays the recovered draft as part of the ordinary review stage.

## Impact

The recovery projection, requirements editor, version-save lineage checks, and workflow documentation change. Existing result artifacts and API contracts are reused.
