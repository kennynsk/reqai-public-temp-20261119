# Текущий продуктовый workflow

ReqAI поддерживает один четырёхэтапный сценарий «Подготовка требований»: «Контекст» → «Требования» → необязательное «AI-исследование» → «Финальная версия».

| Этап | Durable mode | Backend execution |
| --- | --- | --- |
| Декомпозиция и ручная проверка | `DECOMPOSITION` | chunked decomposition → merge → редактирование → immutable requirements version |
| Исследование сохранённой версии | `REQUIREMENTS_INSIGHTS` | один специализированный insights prompt → карточки улучшений → выбор пользователя → финальная версия |

Браузер не оркестрирует LLM-цепочки. Вход хранится как artifact, параметры исполнения фиксируются в `configuration_snapshot`, а статус и результат загружаются по `jobId`. Модель выбирается из настроенного каталога; job сохраняет приоритетный порядок и фактически использованную модель.

В «Настройках AI» можно выключить независимую проверку для следующих
запусков декомпозиции и исследования. По умолчанию она включена. Выбор
запоминается в браузере и фиксируется для каждой новой задачи. В режиме без
критика сохраняются инструкции BABOK и проверка формата, а журнал сообщает,
что независимая проверка пропущена.

Если после проверки входа модель или проверка результата исчерпала попытки,
задача может завершиться с `SUCCEEDED / PARTIAL`. В декомпозиции открывается
обычный реестр с черновиком из доступных типизированных формулировок. Одна
плашка предлагает сверить черновик с исходной задачей. Конкретные вопросы
показаны у связанных требований. Типы исходных связей сохраняются и формируют
вложенность во вкладке «Связи». Пользователь редактирует и сохраняет
черновик целиком. Исходный ответ AI, включая текст без определённого типа,
доступен для просмотра. В AI-исследовании открывается сохранённая входная версия требований
для редактирования и финализации. Версии сохраняются обычным способом.
Отмена и ошибки проверки входа сохраняют свои штатные статусы.

В истории частичное AI-исследование отображается как «Готово частично».
До первой записи финала экран показывает, что финальная версия ещё не
сохранена. После записи он показывает время сохранения финальной версии.
Задача и экспорт используют одну актуальную финальную версию, включая
принятые и сохранённые предложения связанного исследования. Версии привязаны
к задачам, в которых они были сохранены. Исторические исследования доступны
для просмотра, а финальная редакция сохраняется на базе текущего итога.
Журнал исследования фиксирует стадию, код и путь нарушения формата ответа
без содержимого ответа модели.

## Сохраняемое поведение

- история и фильтры задач;
- постоянные ссылки `/tasks/{jobId}`;
- SSE reconciliation и корректная отмена;
- lineage декомпозиции, reviewed version и финальной версии;
- «Журнал задачи» сразу открывает хронологию, а подробности записей доступны согласно ролям. Экран задачи сообщает, как продолжить с частичным результатом;
- read-only просмотр исторических задач удалённых режимов и скачивание доступного result artifact.

Создание, retry и reset исторических режимов запрещены. Миграционная граница и rollback описаны в [legacy-mode-retirement.md](legacy-mode-retirement.md).
